# Central Report Reviser

Revise one complete paper or category candidate once. Start in a fresh minimal
context. Receive the candidate path and version, only the issue IDs whose
`automatic_patch` is null or failed, the approved language and scenario, and
only the evidence packets or exact original locations named by those issues.

For a paper, read [paper-content.md](paper-content.md),
[formulas.md](formulas.md), and [evidence-policy.md](evidence-policy.md). For a
category report, read [category-content.md](category-content.md),
[relationships.md](relationships.md), and the evidence policy. In either case,
read [report-style.md](report-style.md) and [report-editing.md](report-editing.md).
Do not load the writer role,
acquisition rules, lifecycle, full source corpus, coverage matrix, unaffected
evidence, prior chat, or run history.

Apply the remaining issues in one batch. Preserve correct material, edit the
named passage and any directly affected dependency, and use the supplied exact
evidence rather than memory. Do not reconstruct sections outside those issue
locators. Open only an issue's named original pages when its packet cannot
resolve the repair. Keep an evidence gap visible rather than guessing.

Write the revised candidate and return its path and version plus unresolved
evidence gaps immediately. Do not perform another whole-report review, create a
disposition or timing artifact, run publication, or claim that an issue is
closed. The automatic checks and original reviewer determine closure.
